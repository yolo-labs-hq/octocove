# ADR-0006: Webhook operations and signing-key overlap

Status: accepted. Builds on webhook recovery alerts and dispatch.

Parked and cancelled deliveries are immutable terminal evidence, not a mutable retry queue. The original human creator is the subscription owner. [ADR 0009](0009-machine-event-authority.md) extends ownership to registered machines with separate event permissions. Inspection requires their current `webhooks:create` authority; replay and re-drive require their current `webhooks:replay` authority. Another project administrator cannot take ownership. Creator identity always uses the stored issuer/subject tuple. Reactivation retains the existing creator-only `webhooks:create` requirement.

Add `GET /webhooks/{id}/deliveries` (parked or cancelled, bounded keyset), `POST /webhooks/{id}/deliveries/{deliveryId}/redrive` and `POST /webhooks/{id}/rotate-secret`, also under `/v1`. Inspection commits `webhook.deliveries_inspected` evidence before returning, including only hook ID, selected status and count. This read telemetry is excluded from domain event delivery to avoid inspection feedback. Re-drive uses the existing audited `webhook.replay_requested` transition and idempotent replay reservation for the original event's exact audit interval, binding the source delivery ID into both the replay audit refs and request hash. It creates a new lineage and fresh 24-hour window without modifying the original delivery. A disabled hook must first be explicitly reactivated. Retried writes reauthorize and return the committed receipt.

Automatic suspension uses existing `webhook.disabled` with system actor and `membership-revoked` reason. A database status trigger appends the audit row atomically with membership-trigger or scheduler suspension. Failure to append rolls back revocation/suspension; there is no successful unaudited transition. Revocation-before-send remains mandatory.

Signing rotation appends `webhook.secret_rotated` with public current/previous signing key IDs and overlap expiry, never secret material or destination URLs. The original key ID is `initial`; each rotation uses its immutable receipt ID. The receiver must install the supplied new secret before rotation, then map the returned ID to it. Each outbound attempt sends exactly one HMAC and `Octocove-Signing-Key-Id`. Attempts prepared before rotation may send with the previous key strictly before `overlapUntil`; newly prepared attempts, including retries of older deliveries, use the new key. After overlap, a prepared old-key attempt fails closed and retries with the new key. Receivers select only the named key and reject expired previous keys; they must not silently try both. Retain the usual raw-body verification, constant-time comparison, five-minute timestamp window and event dedupe. A request already issued cannot be retracted. The overlap is an explicit integer 1–86400 seconds; a further rotation is rejected while overlap remains active, so at most two generations are accepted. Identical secrets are rejected. Concurrent rotations use a generation/ciphertext CAS; conflicting bodies or generations return 409.

The previous signing secret is retained by the receiver and any already prepared attempt only, never in a second server-side vault column. Encryption keyring rewrap remains independent, unchanged. Rotation replaces the current encrypted signing secret but does not change destination, membership or delivery evidence. All sends retain public DNS validation, pinned numeric IP, TLS hostname verification, redirect refusal and final revocation/deadline checks.

Parked delivery-window alerts reuse the outbox recovery sink (the configured trusted operations sink, `RECOVERY_ALERT_URL`), with a stable per-delivery idempotency key, bounded draining and identifier-only payload. An immutable acknowledgement row is written only after successful sink acceptance. Missing configuration or sink failure leaves the alert retryable on outbox recovery sweeps; this is at-least-once alert delivery.

Vocabulary changes are synchronized in GLOSSARY, API, OpenAPI, the collaboration record, code allowlist and database CHECK. No new delivery state or credential authority is introduced.
